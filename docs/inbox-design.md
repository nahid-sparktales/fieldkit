# Inbox UX review

The review covered finding and prioritizing work, ticket ownership, human takeover, approval review, replies and internal notes, assistant workflows, evidence, knowledge-gap follow-up, and desktop/mobile navigation.

## What changed

| Finding                                                                                                                                                | Implemented behavior                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generic badges hid the difference between approval requests, handoffs, and active conversations. The old status filter omitted handoffs and approvals. | Named, counted queues: **Needs a person** (red), **Awaiting approval** (amber), **Agent active** (blue), **Resolved** (green). Labels and symbols accompany color. Human takeover, expired approvals, and invalidated approvals receive attention instead of appearing active.                                 |
| Names and subjects gave little context, and the queue did not pick up unrelated new tickets.                                                           | Public-message previews, channel labels, full timestamp tooltips, search across visible conversation context, assignee filters, a refresh button, and a 15-second refresh while the page is visible. The selected thread still uses SSE.                                                                       |
| Assistant workflows and technical details displaced the conversation.                                                                                  | Conversation, Support assistant, and Activity & tools tabs. The conversation is the default. Gap flags and regression-test links live with the investigation tools.                                                                                                                                            |
| Assignment, takeover, priority and resolution competed for attention.                                                                                  | A compact ticket header, separate ownership/status controls, explicit agent-paused text, and a clear Resolve/Reopen control. Actions show errors or completion feedback next to the ticket.                                                                                                                    |
| Approvals showed a raw JSON block.                                                                                                                     | A labeled action card with exact parameters, readable supported refund amounts, expiration, approval safeguards, and owner/admin requirements. Expired approvals cannot be clicked. Execution still uses the existing exact-approval confirmation and server-side revalidation.                                |
| Switching tickets discarded unsent replies; private notes were easy to confuse with customer messages.                                                 | Per-ticket in-memory drafts, a visible draft preview, amber private-note composer and messages, explicit audience labels, disabled empty/pending sends, and Cmd/Ctrl+Enter. Failed sends keep the draft and its request key for retry. Switching tickets during a request cannot clear another ticket's draft. |
| The narrow layout stacked the queue over the ticket.                                                                                                   | One pane at a time, a Back to conversations control, restored queue focus, and keyboard-operable tabs. The conversation and composer remain together.                                                                                                                                                          |
| Message times lacked the day and success/error colors differed across sections.                                                                        | Full date/time tooltips and visible dates on messages; the main app's shared badges use consistent success, warning, attention and activity colors.                                                                                                                                                            |

## Boundaries

Queue counts and filtering apply to the most recent 200 conversations returned by the existing API; the queue says “latest 200” when that limit is reached. No global totals are implied. Drafts survive switching tickets, workspaces, and app sections during the current sign-in. They are not written to local storage, saved across reload/sign-out, or synced between devices. Leaving/reloading the browser with an unsent draft triggers the browser's standard warning.

The API's new `last_message` preview includes only customer, assistant, or staff messages, never private notes or system records. It retains customer/workspace access checks. Approval expiry is exposed in list metadata only to staff. Resolving a ticket does not imply customer-confirmed resolution, and changing colors does not grant approval permissions.

Motion is limited to short hover/press feedback; reduced-motion and increased-contrast preferences are supported. No animation or UI dependency was added.
